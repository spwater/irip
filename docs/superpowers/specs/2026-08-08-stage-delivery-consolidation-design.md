# IRIP 阶段性交付文档整理设计

## 目标

为 IRIP 建立一份可供后续开发与 LLM 直接使用的最新上下文入口，减少历史 PRD、架构稿、评审报告和发布记录之间的重复与冲突。历史资料不删除，统一迁入 `archived/` 并保留原目录层级，方便追溯。

## 事实来源

阶段性交付文档按以下优先级判断项目现状：

1. 当前代码、数据库迁移、配置和测试；
2. 当前 Git 状态、近期提交及能够实际运行的质量检查；
3. 仍在使用的常驻文档；
4. 历史 PRD、架构稿、评审和发布报告。

旧文档与实现冲突时，以实现和验证结果为准，并在交付文档中明确记录差异或风险，不沿用未经验证的历史结论。

## 活跃文档结构

整理后，活跃文档分为两类：

- 唯一上下文入口：`docs/STAGE_DELIVERY.md`。
- 常驻操作资料：根目录 `README.md`，以及安装、开发约定、领域不变量、用户指南、上线指南、运维指南和设计语言等仍能指导实际操作的文档。

`docs/STAGE_DELIVERY.md` 至少包含：

- 文档定位、适用版本、代码基线和阅读顺序；
- 产品目标、当前阶段与已交付能力；
- 当前系统架构、核心模块、关键数据流与领域不变量；
- 数据库迁移、运行环境、部署和开发入口；
- 测试矩阵、最近一次实测结果及未执行项；
- 多轮开发和调试中确认的关键问题、修复方式与经验；
- 已知风险、技术债、限制和下一阶段建议；
- 活跃文档清单及 `archived/` 历史资料索引。

文档只写能够从仓库或实测结果支持的事实。无法在当前环境验证的内容标为“未验证”，不把旧报告中的通过数字直接写成当前结果。

## 保留范围

以下资料继续留在活跃目录：

- `README.md`；
- `docs/onboarding.md`、`docs/conventions.md`、`docs/tideline-design-language.md`；
- `docs/architecture/` 中的当前系统概览和领域不变量；
- `docs/data-onboarding/`、`docs/model-onboarding/`、`docs/operations/`、`docs/user-guide/` 中仍与当前代码相符的操作指南；
- 本次新增的 `docs/STAGE_DELIVERY.md`。

保留项在整理时逐份核对。如果文档明显描述已经不存在的命令、路径或能力，则不因目录名称而强行保留，改入归档并在交付文档中说明。

## 归档范围与布局

下列内容视为被阶段性交付文档取代的历史资料：

- 阶段性 PRD、架构设计和配套 Mermaid 图；
- 重构、补救、清理和实现计划；
- 代码评审、架构评审、发布报告、验收快照和旧待办；
- 根目录中的阶段性评估或压缩报告；
- `deliverables/` 下的既往交付稿。

文件移动到仓库根目录的 `archived/`，并镜像原路径，例如 `docs/arch-v0.md` 移至 `archived/docs/arch-v0.md`，`deliverables/architecture-review-2026-08-08.md` 移至 `archived/deliverables/architecture-review-2026-08-08.md`。这样可以避免同名冲突，也便于通过原路径定位历史来源。

归档目录新增 `archived/README.md`，说明归档日期、用途、目录约定和“历史内容不得作为当前实现依据”的规则。

## 链接与入口调整

- 更新根目录 `README.md` 的文档索引，将 `docs/STAGE_DELIVERY.md` 放在首位。
- 删除或改写 README 中指向已归档文档的活跃链接；需要保留历史入口时，明确标注“历史资料”。
- 阶段性交付文档只链接活跃资料和归档总索引，避免为大量历史文件制造新的上下文负担。
- 迁移后检查仓库内相对链接，确保活跃文档不再误指旧位置。

## 验证标准

整理完成必须满足：

1. `docs/STAGE_DELIVERY.md` 能独立回答项目是什么、目前做到哪里、如何运行和验证、有哪些风险、下一步做什么。
2. 活跃目录中不再散落被取代的阶段性报告；历史文件均可在 `archived/` 找到。
3. 常驻操作资料保持原路径，且交付文档列出其用途。
4. README 的活跃链接有效；仓库内没有指向已迁移旧路径的未说明链接。
5. Git 差异主要表现为可追踪的 rename 和少量新文档/索引修改，不删除历史内容。
6. 文档中的版本、测试数量和质量结论均注明来源或实测时间；未验证项不会写成已通过。

## 非目标

本次不修改业务代码、数据库迁移或运行配置，不借文档整理扩展产品范围，也不处理与文档无关的技术债。若验证发现代码问题，只记录到阶段性交付文档，除非问题会阻止本次文档校验。
