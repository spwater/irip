## 0. 原始需求复述

IRIP"研究分析与发布成果"模块设计方案（`docs/superpowers/specs/2026-08-05-research-analysis-and-publication-design.md`）建议拆为 5 个子项目分阶段建设。本期交付**第 2 个子项目"可信执行"**，在阶段 1"研究域基础"已交付的 Workspace、证据引用、证据快照、功能开关和三栏布局之上，实现"AI 能分析数据"的完整执行链路。

**阶段 1 已交付基线**：
- Workspace 创建/列表/归档/删除/分叉
- ResearchQuestionVersion 研究问题版本管理
- WorkspaceEvidenceRef 数据引用管理
- ResearchEvidenceSnapshot 证据快照冻结（SHA-256 哈希 + 权限包络 + 字段清单）
- CoreFactProvider 只读适配
- 功能开关 + `research:use` 权限
- 前端三栏布局（左栏数据面板 / 中栏研究画布 / 右栏 AI 助手占位）

**本期范围**：
1. AI 分析计划生成与计划级授权
2. Analysis Run 后台持久化运行 + DAG 步骤编排
3. 上下文路由与 500K token 硬上限
4. Python 沙箱执行安全
5. 20 用户并发与公平调度
6. 前端右栏 AI 助手激活 + 中栏 Run 进度 + 排队 UI

**基线约束**：延续阶段 1 的模块隔离原则——新模块不反向侵入老系统，只通过只读接口使用原数据；所有研究域实体使用 `research_*` 命名空间；关闭或删除新模块后原系统正常工作。

## 2. 用户故事

**US-1 — AI 提出分析计划**
> 作为研究人员，我想在冻结证据快照后让 AI 自动检查数据结构与质量并提出步骤化分析计划，以便我在执行前了解 AI 将如何分析我的数据、使用什么方法、是否全量覆盖，并在确认后让 AI 连续完成而不需要每步都来打断我。

**US-2 — 后台运行与进度恢复**
> 作为研究人员，我想提交分析 Run 后关闭页面做其他事情，重新进入 Workspace 时能查看 Run 的实时进度、已完成步骤的输出和日志，以便长时间分析不阻塞我的工作流，且随时可以回来跟进或取消。

**US-3 — 公平排队**
> 作为研究人员，当同时活跃的 Analysis Run 已达平台上限时，我想看到自己在队列中的位置、前方有多少用户以及预计等待时间，以便我决定是等待还是稍后再来，而不是盲目等待。

**US-4 — 与 AI 持续对话**
> 作为研究人员，我想在分析过程中通过右栏 AI 助手与 AI 持续对话，让它解释中间结果、建议下一步方向或修复错误，以便我在 AI 自主执行的同时保持理解和参与，而不是完全黑箱等待。

**US-5 — 覆盖声明透明**
> 作为研究人员，我想在每次分析时看到"数据覆盖率 X% | LLM 阅读率 Y% | 是否抽样: 否"这样的覆盖声明，以便我确信 AI 是否真正阅读了全部数据，而不是静默抽样后给出不准确的全量结论。

## 3. 需求池

### P0 — Must Have

| ID | 需求 | 验收标准 |
|----|------|---------|
| P0-1 | **AnalysisPlanVersion 不可变版本**：AI 检查证据快照的数据结构与质量后，生成步骤化分析计划并保存为不可变版本。计划包含每步要回答的问题、使用哪些证据、使用 Python/LLM/知识库/混合方式、是否全量/分块/抽样、预期输出、主要假设和风险 | AnalysisPlanVersion 创建后不可修改；包含全部必需字段（步骤列表、每步问题/数据/方法/策略/输出/风险）；版本号递增 |
| P0-2 | **计划级授权**：用户确认计划后，AI 可在计划范围内连续编写 Python、运行、修复错误和调整图表，不必逐步打断。新增数据、改变研究目标、首次调用知识库、扩大资源级别、发布成果需重新确认 | 确认后的计划记录授权状态和授权时间；AI 在范围内连续执行不触发重新确认；越界行为（新增数据/改变目标/首次知识库/扩大资源/发布）触发重新确认提示 |
| P0-3 | **AnalysisRun 后台持久运行**：Run 在后台持续运行，用户关闭页面或退出登录不中断。重新进入 Workspace 可查看实时进度、阶段输出和日志 | Run 提交后脱离前端会话独立运行；重新进入可看到当前状态和已完成步骤输出；Run 状态持久化在 PostgreSQL 中，不依赖 Redis 单一来源 |
| P0-4 | **Run 状态机**：Run 状态包括 queued / planning / running / partially_succeeded / succeeded / failed / cancelled。状态转换合法且可审计 | 状态转换遵循定义的合法路径；非法转换被拒绝；每次状态变更产生审计记录 |
| P0-5 | **DAG 步骤编排**：分析计划以 DAG（有向无环图）保存。每个 AnalysisStep 记录步骤状态、依赖关系和执行结果。某步失败后其依赖步骤停止；无依赖关系的分支仍可继续 | DAG 结构在数据库中持久化；依赖关系可查询；失败步骤的下游自动停止；无依赖分支不受影响 |
| P0-6 | **发布资格校验**：只有依赖闭包全部成功的步骤输出才具备发布资格。从部分失败 Run 发布独立成功结果时，必须标明源 Run 为部分成功并保留失败步骤审计摘要 | 发布前系统校验依赖闭包完整性；部分成功 Run 的发布成果标注"源 Run 部分成功"；失败步骤审计摘要保留 |
| P0-7 | **重跑创建新 Run**：重跑不覆盖旧 Run，而是创建新的 AnalysisRun，绑定新的或同一证据快照 | 重跑后旧 Run 保留且不可变；新 Run 有独立 ID；两个 Run 可同时查看 |
| P0-8 | **取消 Run**：用户可取消运行中的 Run。取消后已完成结果仅作临时记录，不能直接发布 | 取消后 Run 状态变为 cancelled；已完成步骤输出标记为临时；发布校验拒绝 cancelled Run 的输出 |
| P0-9 | **上下文路由 — 平台自动选择模型**：用户不直接选择模型。平台根据规划、代码生成、长上下文、Insight 分析和模型可用性自动路由。每次调用记录供应商、模型、模型版本、提示词版本、工具版本和时间 | 用户界面无模型选择器；每次模型调用记录完整元数据；备用模型切换时显式记录 |
| P0-10 | **自动分析模式区分**：系统按分析步骤自动选择全量计算 / 分块全量扫描 / 直接全量上下文 / 检索探索 / 混合分析。每个步骤保存是否要求全量、是否逐条语义阅读、是否存在跨记录推理、是否允许抽样、预计 token、最终模式和选择原因 | 每个步骤记录模式选择元数据；模式选择有明确原因记录；模式区分可在审计中追溯 |
| P0-11 | **500K 单次数据硬上限**：有效数据预算 = min(500K, model_context_limit - system_and_tool_tokens - research_context_tokens - reserved_output_tokens - safety_margin)。超预算时自动切块全量扫描再分层归并。不允许静默抽样；只有研究目标允许抽样时才可抽样 | 单次模型调用的数据部分不超过 500K tokens；超预算时自动切块；非抽样允许场景下系统不静默抽样；预算计算可在日志中追溯 |
| P0-12 | **覆盖声明**：每次分析向用户显示"自动模式: 混合分析 \| 数据覆盖率 X% \| LLM 阅读率 Y% \| 是否抽样: 否"。数据覆盖率和 LLM 阅读率分别记录，不混为一谈 | 覆盖声明显示在分析结果区域；数据覆盖率与 LLM 阅读率独立计算和展示；抽样状态如实显示 |
| P0-13 | **Python 沙箱安全边界**：每次 Python 执行运行在独立容器或 Pod 中：默认断网、非 root、只读基础镜像、只读挂载证据快照输入包、仅允许写入临时工作目录、不持有核心数据库/对象存储/知识库凭据、不继承 API/Worker 环境秘密、对 CPU/内存/时间/临时磁盘/输出大小设硬限制、结束后由控制面收集白名单输出再销毁容器 | 安全测试通过：沙箱无法访问互联网、核心数据库、MinIO 凭据和宿主机敏感路径；输入只读、输出目录受限、进程非 root、资源超限被终止 |
| P0-14 | **受控输入包**：沙箱不直接读取老系统。Research Orchestrator 在权限校验后生成一次性输入包并预置到沙箱；输出由平台扫描、校验和持久化 | 沙箱内无法获取核心数据库连接字符串；输入包为只读挂载；输出经平台白名单扫描后持久化 |
| P0-15 | **固定版本科学计算镜像**：平台维护固定版本镜像，预装 NumPy / Pandas / SciPy / statsmodels / scikit-learn / Matplotlib / Seaborn。用户不执行 pip install，也不管理虚拟环境。旧 Run 永久记录原镜像摘要 | 镜像版本号可追溯；用户无法在沙箱内安装包；不同镜像版本重跑产生新 Run |
| P0-16 | **资源档位**：标准执行步骤 2 vCPU / 4GB 内存 / 单步 20 分钟 / 5-10GB 临时磁盘 / 输出总量受限。步骤结束后可保温约 3 分钟以支持连续图表调整，空闲后释放。20 分钟限制作用于单个 Python 沙箱步骤，不限制整个 Run | 超时步骤被终止并保留错误分类；保温窗口内可继续执行；重型任务进入独立队列（本期可预留接口） |
| P0-17 | **20 用户并发上限**：最多 20 个不同用户同时拥有活跃 Analysis Run。每用户最多 1 个活跃 Run。每 Workspace 最多 1 个活跃 Run。第 21 个用户进入等待队列 | 20 个用户可同时活跃；第 21 个排队；同一用户多 Run 被拒绝；同一 Workspace 多 Run 被拒绝 |

| P0-22 | **右栏 AI 助手激活**：右栏从占位变为可用，支持持续对话、主动建议和计划说明。AI 可展示生成的分析计划供用户确认 | 对话功能可用（发送/接收消息）；AI 主动推送建议和计划说明；计划确认交互可用 |
| P0-23 | **中栏 Run 进度展示**：研究画布增加 Run 进度条、步骤状态（DAG 节点状态着色）、候选数据/图表预览 | 进度条实时更新；DAG 节点显示 running/succeeded/failed/pending 状态；可预览已完成步骤的输出 |

## 4. UI 设计概要

### 4.1 三栏布局总览（阶段 2 激活后）


### 4.2 右栏 — AI 科研助手（本期从占位激活）

**功能模块**：

1. **持续对话区**：
   - 消息列表（用户消息 + AI 回复），支持多轮上下文
   - 底部输入框 + 发送按钮
   - AI 可在对话中展示：计划说明、中间结果解释、错误解释、后续方向建议
   - 消息可包含代码块（只读展示 AI 生成的 Python）

2. **计划说明卡片**：
   - AI 生成分析计划后，在对话区上方显示结构化卡片
   - 卡片内容：计划标题、步骤摘要（每步问题/方式/策略）、覆盖声明预览
   - 卡片底部"确认计划"和"调整计划"按钮
   - 确认后卡片折叠为"已确认计划 v1"状态条

3. **主动建议**：
   - AI 在关键节点主动推送建议（如"数据质量检查发现 3 条缺失记录，建议加入清洗步骤"）
   - 建议以可折叠的提示气泡形式展示，用户可采纳或忽略

4. **覆盖声明**：
   - 分析进行中，在对话区底部固定显示当前覆盖声明
   - 格式："自动模式: 混合分析 | 数据覆盖率 X% | LLM 阅读率 Y% | 是否抽样: 否"
   - 分块扫描时显示批次进度："批次 3/8 进行中"

### 4.3 中栏 — 研究画布（本期增加 Run 进度）

**新增区域**：

1. **分析计划区**：
   - 展示当前计划的步骤列表（DAG 线性展示）
   - 每步显示：步骤名称、要回答的问题、执行方式（Python/LLM/混合）、状态图标
   - 状态图标：✓ succeeded / ● running + 进度百分比 / ✗ failed / ○ pending / ⊘ skipped
   - 未确认时显示"确认计划"和"调整计划"按钮

2. **Run 进度区**：
   - 当前 Run 编号和状态标签（running / partially_succeeded / failed / cancelled）
   - 总体进度条
   - 已完成步骤数 / 总步骤数
   - 运行时长计时

3. **覆盖声明条**：
   - 在 Run 进度区下方显示，与右栏覆盖声明同步
   - 包含数据覆盖率、LLM 阅读率、是否抽样

4. **候选输出预览区**（本期基础展示，完整管理在子项目 3）：
   - 已完成步骤产生的候选数据、图表和中间工件以缩略卡片形式展示
   - 点击可展开预览
