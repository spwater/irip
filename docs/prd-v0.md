# IRIP Phase V0 产品需求文档（PRD）

## 1. 项目信息

- **Language:** 中文
- **Programming Language:** Python 3.12+（后端）、TypeScript + React（前端）
- **Project Name:** irip-platform
- **原始需求：** 基于《IRIP完整工程逐任务实施计划》中 Phase V0（任务 1-9），构建本地可部署的工业科研智能平台骨架，为后续 L1→L3 证据链与篦冷机 ROM 生命周期提供统一的身份、权限、存储与异步作业基础设施。

---

## 2. 产品目标

1. **建立可部署、可初始化的平台基座**：在全新 Linux 主机上通过 Docker Compose 一键启动，完成数据库迁移、管理员创建、对象存储桶初始化，并验证幂等性。
2. **提供统一的身份认证与细粒度授权**：实现安全的登录/刷新/登出会话生命周期，并基于 RBAC + 对象级 Scope Grant 控制资源访问。
3. **交付可靠的内容存储与异步作业能力**：支持以 SHA-256 内容寻址的工件存储（去重、可验证），以及具备 Outbox、租约、幂等提交的可恢复后台作业。

---

## 3. 用户故事

1. **As a** 平台管理员，**I want** 在全新服务器上执行 `docker compose up --build` 后自动完成初始化并创建管理员账号，**so that** 无需手工配置即可进入平台。
2. **As a** 研究员，**I want** 使用邮箱和密码登录平台，并在刷新页面后仍保持会话，**so that** 可以安全地访问我被授权的功能。
3. **As a** 数据管理员，**I want** 系统按角色和对象范围限制我的访问，**so that** 我只能查看和操作被授权的对象，防止越权。
4. **As a** 研究员，**I want** 上传的实验文件按内容哈希存储并去重，**so that** 相同文件不会重复占用空间，且可通过摘要验证完整性。
5. **As a** 平台用户，**I want** 提交一个后台任务并在页面刷新后继续查看进度，**so that** 长耗时任务不会丢失，且重复提交不会产生重复结果。

## 5. UI 设计稿描述

Phase V0 的 UI 以“最小可用控制台”为目标，采用 Ant Design 布局体系，整体为中文界面。

### 5.1 登录页（LoginPage）

- **布局**：居中卡片式布局，包含平台 Logo/名称、邮箱输入框、密码输入框、登录按钮。
- **交互**：
  - 输入校验：必填、邮箱格式。
  - 登录成功：根据登录前访问的 URL 重定向回目标路由；无目标则进入默认工作台。
  - 登录失败：展示统一错误提示（如“邮箱或密码错误”），不泄露具体失败原因。
- **技术要点**：调用 `/api/v1/auth/login`；refresh token 通过 HttpOnly Cookie 存储；access token 仅保存在内存。

### 5.2 主布局（AppShell）

- **结构**：左侧导航 + 顶部用户信息栏 + 内容区。
- **左侧导航**：根据当前用户权限动态渲染可见菜单；V0 阶段可包含“工作台”“实验与事实”“作业中心”等占位入口。
- **顶部栏**：显示当前用户 displayName、角色标签、退出登录按钮。
- **路由守卫**：未登录访问任意受保护路由时跳转至登录页，并在登录后回跳。

### 5.3 作业抽屉（JobDrawer）

- **触发**：全局悬浮按钮或顶部图标，点击后从右侧滑出抽屉。
- **内容**：列出当前用户提交的作业，包含作业类型、状态、当前阶段、进度百分比、重试/取消按钮。
- **状态恢复**：仅将 job ID 持久化到 localStorage；刷新页面后根据 ID 从 `/api/v1/jobs/{id}/events` 拉取最新状态。
- **状态展示**：使用 Ant Design 的 Progress、Tag、Steps 等组件区分 `running/retry_wait/succeeded/failed/cancelled` 等状态。

## 6. 技术约束（与 V0 相关）

以下约束摘自实施计划 Global Constraints，Phase V0 必须遵守：

1. **部署环境**：单一 Linux 服务器，Docker Engine 24+ 与 Docker Compose 2.24+。
2. **组织模型**：首版本为单组织 + 多部门/实验室，非多租户 SaaS。
3. **时间规范**：所有权威时间戳使用 UTC `timestamptz`；API 输出 RFC 3339；UI 本地化显示。
4. **权威存储**：PostgreSQL 16 为唯一权威存储；Redis 仅作缓存/队列，永不作为权威存储；MinIO 按 SHA-256 内容哈希存储二进制工件。
5. **作业规范**：每个作业必须具备执行版本、输入快照、日志、工件和幂等键。
6. **安全规范**：AI 工具继承当前用户的对象权限，且不得发布标准、直接修改事实、发布 L3、执行任意 SQL 或任意脚本。
7. **界面语言**：UI 以中文优先；稳定编码、API 字段、数据库标识符、源码标识符使用英文。
8. **依赖管理**：运行时依赖必须通过 lockfile 固定；生产镜像禁止使用 floating `latest` 标签。
9. **技术边界**：V0 不引入 Kafka、Flink、OpenSearch、TimescaleDB、Keycloak、Kubernetes 运行时依赖、通用低代码编辑器或自动控制输出。

## 7. 待确认问题

1. **默认管理员密码策略**：bootstrap 从 `IRIP_BOOTSTRAP_ADMIN_PASSWORD` 读取，是否要求首次登录后强制修改？
2. **对象级 Scope Grant 的 UI 管理**：V0 仅提供 API 与种子数据，是否需要在 V0 提供简单的授权管理界面？（当前计划未包含，建议延后至 V1/V3）
3. **作业类型的初始集合**：V0 仅演示 `echo` 作业，是否需要在 V0 就接入文件解析等真实业务作业？（建议保持 V0 轻量，真实作业在 V1 接入）
4. **审计查询入口**：V0 是否提供只读的审计日志查询页面？（当前计划未包含，可列为 P2 或延后）
