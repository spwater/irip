## 1. 项目信息

- **Language:** 中文
- **Programming Language:** Python 3.12+（后端）、TypeScript + React 18（前端）
- **Project Name:** irip-platform
- **原始需求：** 将 `department_id` 扶正为全系统唯一多租户隔离键，`organization` 表及 `organization_id` 列退役；落地对称层级可见性、个人私有数据、root/system 哨兵部门。
- **范围：** 增量需求，基于基线 PRD `prd-department.md`（部门 CRUD）之上，升级隔离模型。不重写部门 CRUD 功能。

## 2. 产品目标

**将 `department_id` 扶正为全系统唯一多租户隔离键，以"对称层级可见性 + 横向白名单"替代恒真的 organization 过滤，在消除概念冗余的同时引入个人私有数据能力，使科研数据的归属、可见范围与隐私控制有统一且无例外的模型。**

| 目标维度 | 说明 | 衡量标准 |
|---------|------|---------|
| G1 隔离模型统一 | organization 退役，department 树成为唯一租户维度，root 承担原组织角色 | 全库无 `organization_id` 残留；RLS 全部锚 `app.current_dept_id`；单组织恒真过滤消失 |
| G2 可见性对称透明 | 父可见子、子可见父（直系祖先链），root 数据全员可见是定理而非特例 | 父部门可见子孙数据 ✓；子部门可见祖先链数据 ✓；root 数据全树可见 ✓；旁系隔离 ✓ |
| G3 私有数据落地 | 面向用户发布的表支持"发布为私有"，仅 owner 本人可见（含管理员） | 私有数据仅 owner 可读（root 成员不可见反例通过）；公开单向不可逆（触发器兜底） |

## 3. 用户故事

### 3.1 部门归属与可见性

> **US-01** — 作为研究员，我希望每条数据明确归属到某个部门，且我能看到我所属部门及其祖先链的数据，以便我在组织内有层次地获取可复用的科研数据，同时旁系部门的数据天然隔离。

> **US-02** — 作为实验室负责人（父部门成员），我希望自动看到下属课题组的全部数据，以便我无需逐个申请权限即可监督下属工作。

> **US-03** — 作为课题组研究员（子部门成员），我希望看到我所属实验室本级的数据，以便我了解实验室层面的公共成果，而不仅限于本课题组。

> **US-04** — 作为任意登录用户，我希望"公共大厅"（root 归属的数据）自动对我可见，以便我无需额外授权即可浏览平台公共组件、预置流程和公共字典。

### 3.2 跨部门数据共享

> **US-05** — 作为数据 owner，我希望将我部门的数据显式共享给指定旁系部门，以便跨部门科研协作时对方可见我的活数据，同时共享可随时撤销、跟随源数据更新。

> **US-06** — 作为被共享方，我希望在数据列表中看到共享给我的数据并明确标注来源，以便区分"我部门的数据"与"共享给我的数据"。

### 3.3 个人私有数据

> **US-07** — 作为研究员，我希望在发布数据时勾选"发布为私有"，使该数据仅我本人可见（包括管理员在内任何其他人都不可见），以便我在数据正式公开前进行个人草稿管理。

> **US-08** — 作为私有数据 owner，我希望在私有数据详情页一键"公开"将其转为部门树可见，且系统明确提示此操作不可逆，以便我在确认数据成熟后安全地公开。

> **US-09** — 作为研究员，我希望私有数据在列表和详情页有醒目标识（名称标红），以便我一眼区分私有与已公开的数据。

### 3.4 部门树管理（re-parent）

> **US-10** — 作为管理员，我希望在部门管理页面调整部门层级（re-parent），且系统在操作前预览影响范围（涉及的数据量、受影响的用户列表），并要求二次确认，以便我安全地调整组织结构而避免可见性误变。

> **US-11** — 作为管理员，我希望调整部门层级后数据归属不变（仅可见范围随树变化），以便组织结构调整不会产生数据搬迁或丢失。

### 3.5 AI 会话可见性

> **US-12** — 作为 AI 会话创建者，我希望我的会话仅对我和被邀请的参与者可见（不受部门树规则约束），以便我的 AI 探索过程不会被上级链翻看。

> **US-13** — 作为 AI 会话参与者，我希望看到会话内的所有消息和橱窗块副本，且这些副本不随源数据权限撤销而回收，以便会话上下文完整保留。

> **US-14** — 作为会话创建者，在邀请新参与者或发布会话时，我希望系统提示"会话内已有的数据副本将随之暴露给新参与者"，以便我知情同意。

### 3.6 管理员权限模型

> **US-15** — 作为管理员，我希望我的全量可见权限来自"我是 root 部门成员"而非特殊开关，以便权限模型统一无例外、可审计。

> **US-16** — 作为管理员，我希望加入 root 部门是受控操作（仅现有 root 成员可加人 + 审计日志），以便系统最高权限的授予可追溯。

> **US-17** — 作为管理员，我希望"系统室"（system 哨兵部门）的敏感数据（密钥、审计事件、备份记录）仅 root 成员可见，以便管理性数据自然隔离、无需额外机制。

## 4. 需求池

### P0 — 必须（本增量验收门强制要求）

| 编号 | 需求描述 | 验收标准 |
|------|---------|---------|
| T0-01 | **department_id 扶正为唯一隔离键**：GUC `app.current_org_id` → `app.current_dept_id`，新增 `app.current_user_id`；Principal 用 primary department_id 替代 organization_id；QueryScope 切换为 department_id + 可见部门集。 | 连接默认 fail closed（`app.current_dept_id=''`）；session_scope 从 principal 设置两个 SET LOCAL；QueryScope 过滤按 dept + 白名单。 |
| T0-02 | **RLS 策略重构**：26 张租户表策略从 `organization_id` 等值切换为对称层级可见性函数 `current_visible_dept_ids()` + 横向白名单 `visible_departments @>`。A 类表含私有分支；B 类表去掉白名单分支。 | A 类：私有仅 owner OR (tree AND (层级可见 OR 白名单))；B 类：层级可见；管理员全可见由 root 成员 + 通道①自动达成，无 is_admin/bypass。 |
| T0-03 | **对称可见性落地**：实现 `current_visible_dept_ids()` 递归 CTE 函数——向下穿透（子孙全集）∪ 向上回溯（直系祖先链），一条 SQL 搞定，root 公共语义自然覆盖。 | 父见子 ✓；子见祖先链 ✓；root 数据全员可见 ✓；旁系互不可见 ✓；department 表策略 `id IN (SELECT current_visible_dept_ids())`。 |
| T0-04 | **A 类表补列**：fact、parameter、evidence_set、artifact、model、transformation_recipe、component、flow_definition、industrial_object、equipment 补 `department_id NOT NULL` + `visible_departments JSONB DEFAULT '[]'`（GIN 索引）+ `visibility_scope TEXT DEFAULT 'tree'` + `owner_user_id UUID`。 | 存量回填按 ADR §4 依据；NOT NULL 约束生效；GIN 索引 `jsonb_path_ops`。 |
| T0-05 | **B 类表补列**：job、flow_run、derivation_run、audit_event、scope_grant、secret、backup_record、connector 各表、app_user 补 `department_id NOT NULL`（不开放 visible_departments）。 | 存量回填按 ADR §4 依据；敏感档数据挂 system 哨兵。 |
| T0-06 | **个人私有数据**：发布表单提供"发布为私有"勾选框（默认不勾）；私有数据仅 owner 本人可见（RLS 强制，含 root 管理员不可见）；详情页名称标红 + 操作栏"公开"按钮（二次确认提示不可逆）；DB 层 BEFORE UPDATE 触发器禁止 `tree → private` 回退 + `owner_user_id` 不可改。 | 私有仅 owner 可读（反例：root 成员不可见）；公开单向不可逆（触发器 RAISE EXCEPTION）；公开操作写审计日志。 |
| T0-07 | **root / system 哨兵部门**：bootstrap 改为创建 root（code='root'，display_name=环境变量 `IRIP_ROOT_DEPT_NAME`）+ system（code='system'，root 直系子部门）哨兵节点；root 的 display_name 管理员可改，code 锁定；哨兵节点不可 re-parent、不可禁用、不可删除。 | bootstrap 幂等创建两哨兵；admin 用户挂 root；root display_name 可改、code 不可改；哨兵保护 CHECK/触发器生效。 |
| T0-08 | **AI 会话可见性扩展**：ai_conversation + ai_message 不进部门树规则，可见者 = 创建者 + 参与者（conversation_participant 唯一通道）；RLS 策略扩展 `OR id IN (SELECT conversation_id FROM conversation_participant WHERE user_id = current_user)`；用 SECURITY DEFINER 函数防两表互引用递归。 | 创建者 + 参与者可见 ✓；同部门非参与者不可见 ✓；上级链不可见 ✓；副本语义（copy-on-share）：消息与橱窗块为发送时副本，不随源数据更新/权限撤销回收。 |
| T0-09 | **结构数据全员可读**：provenance_edge、object_relation、object_type_dict 等字典、department 自身不带租户列、不设 RLS；写入限管理员角色。 | 登录用户均可读结构数据；谱系查询中不可见端点显示"无权限节点"占位而非断链。 |
| T0-10 | **跨部门共享（白名单）**：A 类表共享沿用 `visible_departments` 白名单 + GIN 索引；共享为显式动作（owner 或管理员操作），不走后代自动可见。 | 白名单 `@>` 精确匹配、不随树扩散；共享可撤销；共享数据跟随源更新。 |
| T0-11 | **Worker 写入路径**：Celery worker payload 增加 `department_id`（提交者上下文快照）；session_scope 用该值设置 GUC；Beat 定时任务按产出物敏感度挂 root 或 system。 | worker 无用户上下文时写入 root（公共档）或 system（敏感档）；审计字段保留 created_by。 |
| T0-12 | **迁移阶段 1（加列回填，双跑）**：一个迁移批次 A/B 类表 ADD COLUMN department_id（先 NULL）→ 回填 → SET NOT NULL；A 类同步加 visible_departments + visibility_scope + owner_user_id；department 加 root/system 哨兵行 + 唯一约束改造；应用层双写。 | 此阶段 RLS 仍锚 org，行为完全不变，可随时中止；回填脚本输出逐表审计报告。 |
| T0-13 | **迁移阶段 2（切换）**：Principal/GUC/策略换锚（§5），应用查询切换；feature flag 或快速回滚迁移保障；worker 同步切换；前端字段切换。 | 切换后 RLS 锚 dept，fail closed 方向安全（漏改表现为"看不到"而非"看到不该看的"）。 |

## 5. UI 设计稿描述

### 5.1 数据创建表单 — 归属部门选择器 + 发布为私有勾选

**适用页面**：fact、parameter、evidence_set、artifact、model、transformation_recipe 等面向用户发布的数据创建/编辑表单。

```
┌─────────────────────────────────────────────────────┐
│  新建实验与事实                                        │
│                                                       │
│  * 所属部门    [无机非材料实验室 ▾]    ← 多部门用户可见 │
│                  ├── 公共（IRIP 研究院）   ← root 特殊标签│
│                  ├── 无机非材料实验室                    │
│                  │    └── 水泥课题组                     │
│                  └── 固废实验室                           │
│                                                       │
│  名称    [___________________________]                 │
│  ...（其他业务字段）                                   │
│                                                       │
│  ☐ 发布为私有                                         │
│  ┌───────────────────────────────────────────────┐   │
│  │ ℹ 勾选后，此数据仅您本人可见，包括管理员在内   │   │
│  │   的其他任何人都不可见。后续可一键"公开"转为   │   │
│  │   部门可见，但此操作不可逆。                   │   │
│  └───────────────────────────────────────────────┘   │
│                                                       │
│              [取消]  [保存草稿]  [发布]                 │
└─────────────────────────────────────────────────────┘
```

**交互要点**：
- **归属部门选择器**：单部门用户自动填充 primary 部门、隐藏选择器；多部门用户显示下拉树（Ant Design `TreeSelect`），默认选中 primary。root 显示为"公共（{机构名}）"，system 哨兵不出现在选择器中（仅内部使用）。
- **发布为私有勾选框**：默认不勾。勾选后下方展开提示文案说明私有语义（仅 owner 可见、含管理员不可见、可公开但不可逆）。设备/工业对象表单不暴露此勾选框（资产归部门不归个人），但数据层仍带两列（数据层无例外）。
- **提交校验**：department_id 必填；visibility_scope 随勾选状态设为 `'private'` 或 `'tree'`；owner_user_id 自动填当前用户。

### 5.2 私有数据详情页 — 标红 + 公开按钮

**适用页面**：私有数据的详情/查看页（fact 详情、model 详情等）。

```
┌─────────────────────────────────────────────────────┐
│  ← 返回列表                                           │
│                                                       │
│  🔴 水泥水化热预实验数据（草稿）     [🔒 私有]          │
│  ─────────────────────────────────                    │
│  归属：无机非材料实验室 · 创建者：张三 · 2026-08-02    │
│                                                       │
│  ...（数据详情内容）                                   │
│                                                       │
│  ┌───────────────────────────────────────────────┐   │
│  │  操作栏                                         │   │
│  │  [编辑]  [删除]  [分享]  [🔴 公开]               │   │
│  └───────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘

点击"公开"后弹出确认对话框：
┌─────────────────────────────────────────────────────┐
│  ⚠ 确认公开此数据？                                   │
│                                                       │
│  公开后，此数据将按所属部门的可见性规则（对称层级 +   │
│  横向白名单）对所有可见用户开放。                       │
│                                                       │
│  此操作【不可逆】，公开后无法再转为私有。              │
│                                                       │
│              [取消]  [确认公开]                        │
└─────────────────────────────────────────────────────┘
```

**交互要点**：
- **名称标红**：私有数据的标题/名称以红色文字渲染，旁附 🔒 私有标签（红色 Tag），一眼区分。
- **公开按钮**：操作栏提供红色"公开"按钮；点击弹出二次确认对话框，明确提示"不可逆"。确认后调用 `PATCH` 将 `visibility_scope` 改为 `'tree'`，成功后名称恢复常规颜色、私有标签消失。
- **不提供"转私有"按钮**：应用层只暴露"公开"动作，不暴露任何"转私有"入口（单向不可逆，DB 触发器兜底）。
- **非 owner 不可见**：私有数据对非 owner 用户完全不可见，不会出现在其列表或详情中。
