# 科研数据平台 AI 助手分析橱窗及可视化升级 PRD

## 1. 项目信息

| 项 | 值 |
|---|---|
| 文档语言 | 中文 |
| 技术栈（前端） | React 18 + TypeScript 5.7 + Vite 5 + Ant Design 5 + TanStack Query/Router + Zustand |
| 技术栈（后端） | Python 3.12+ / FastAPI / SQLAlchemy（async）/ PostgreSQL 16 / Redis 7 |
| 项目名称 | `irip-ai-showcase` |
| 改造性质 | 增量升级（基于现有 AI 助手模块，不另起炉灶） |
| 原始需求复述 | 在现有 AI 助手两栏布局基础上，补充左侧历史对话搜索、右侧增加"分析橱窗"（与每段对话独立绑定的成果留存区）、消息内容块化并支持加入橱窗、在保留 ECharts 基础上引入 Plotly 增强科研可视化、支持基于橱窗内容的成果导出/摘要生成。 |

### 1.1 现有系统现状（改造基线）

- **布局**：左侧对话列表（260px）+ 中部对话区（flex:1），右侧空间未利用。
- **对话管理**：新建/切换/置顶/归档/删除，**无搜索**。
- **消息渲染**：`react-markdown` + KaTeX 数学公式 + ECharts 图表（` ```echarts ` 代码块），整条消息渲染，**无块级操作**。
- **数据加载**：底部"载入实验数据"Modal，按任务分组选样品，注入 `system_context`。
- **后端 API**：对话 CRUD + 消息发送/列表 + Provider 状态，**无橱窗相关接口、无搜索接口**。
- **数据模型**：
  - `ai_conversation`（id / org_id / user_id / title / provider_mode / pinned / archived / system_context / created_at / updated_at）
  - `ai_message`（id / conversation_id FK CASCADE / role / content:Text / tool_calls_json:JSONB / citations_json:JSONB / uncertainty / created_at）
  - 消息 `content` 为单一文本字段，**无块级结构**。

## 2. 产品目标

1. **让重要分析成果不被聊天淹没**：在对话右侧新增"分析橱窗"，用户可将图表、表格、关键结论等精选内容一键留存，形成与该对话长期绑定的成果面板，刷新/重登/切换对话后均可恢复。
2. **充分利用宽屏空间，保持左侧简洁**：从两栏升级为三栏（左历史对话 + 中当前对话 + 右分析橱窗），左侧保持普通列表 + 新增搜索，右侧收放自如，中部保留完整分析过程。
3. **增强科研可视化与成果输出能力**：在保留 ECharts 常规二维图表的基础上引入 Plotly 支持误差棒/箱线/三维等科研图表，并支持基于橱窗内容生成分析摘要或导出成果。

## 3. 用户故事

> 格式：作为 [角色]，我希望 [功能]，以便 [价值]。

1. **作为科研人员**，我希望在左侧历史对话列表中搜索关键词，以便快速找到之前某次分析对话，而不必逐条翻阅。
2. **作为科研人员**，我希望将对话中 AI 生成的重要图表/表格/结论一键"加入橱窗"，以便这些成果不被后续聊天内容淹没，随时可以回看。
3. **作为科研人员**，我希望切换或重新打开某段历史对话时，右侧橱窗同步恢复之前留存的全部内容及其排序，以便延续之前的分析工作。
4. **作为科研人员**，我希望点击橱窗中的某张图表卡片后，中部聊天区自动滚动到该图表的原始消息位置并短暂高亮，以便追溯该结论的上下文。
5. **作为科研人员**，我希望基于已加载实验数据生成科研级图表（如误差棒图、三维散点图），并能把图表加入橱窗，以便完成更专业的数据分析。
6. **作为科研人员**，我希望将橱窗中的精选内容一键导出为分析摘要或数据报告，以便整理科研成果、分享给同事。
7. **作为科研人员**，我希望橱窗卡片保留与原始实验数据（样品、字段、数据范围）的关联信息，以便后续复核结果来源。

## 4. 需求池

### 4.1 P0 — 必须完成（13 项，对应需求说明书"必须完成"清单）

#### P0-01 左侧历史对话搜索

**描述**：在现有左侧对话列表顶部增加搜索输入框，搜索范围覆盖对话标题、用户提问内容、AI 回答中的文本内容。搜索结果可直接点击打开对应历史对话。保留现有的置顶/归档/删除功能不受影响。

**验收标准**：
- AC1：对话列表卡片上方渲染一个搜索输入框（带搜索图标、可清除）。
- AC2：输入关键词后，列表实时过滤，匹配范围包括对话标题、该对话下所有 user 消息内容、所有 assistant 消息的文本内容（不含 JSONB 工具调用结构）。
- AC3：点击搜索结果中的对话，中部加载该对话聊天、右侧同步加载橱窗，与直接点击列表项行为一致。
- AC4：搜索框清空后恢复显示完整对话列表。
- AC5：归档视图（showArchived）下搜索同样生效。
- AC6：搜索为后端全量检索（ILIKE / 全文索引），前端仅传 keyword 参数，不在前端拉取全部消息做过滤。

#### P0-02 右侧增加分析橱窗

**描述**：在现有两栏布局右侧新增"分析橱窗"面板，宽度约 360px，与左侧对话列表、中部对话区共同构成三栏布局。橱窗面板可收起/展开，收起后保留一个窄边条显示图标与当前橱窗卡片数量。

**验收标准**：
- AC1：默认布局为三栏：左 260px + 中 flex:1 + 右 ~360px。
- AC2：右侧顶部有标题"分析橱窗"及卡片数量角标、收起按钮。
- AC3：点击收起按钮后右侧面板折叠为窄边条（~48px），显示橱窗图标 + 卡片数；再次点击展开恢复原宽度。
- AC4：中部对话区宽度随右侧收起/展开自适应，不出现溢出或横向滚动。
- AC5：无选中对话时，橱窗显示空状态引导文案。

#### P0-03 橱窗与历史对话独立绑定

**描述**：橱窗内容与每段历史对话一对一独立绑定，不是全局收藏夹。切换对话时中部加载聊天、右侧同步加载该对话的橱窗；新建对话时橱窗为空。橱窗数据存储在数据库中，通过 `conversation_id` 关联。

**验收标准**：
- AC1：数据库新增 `ai_showcase_item` 表，以 `conversation_id` 外键关联 `ai_conversation`，`ondelete=CASCADE`。
- AC2：切换对话时，右侧橱窗自动加载目标对话的橱窗卡片列表，顺序与之前保存一致。
- AC3：新建对话时橱窗为空，显示空状态。
- AC4：不同对话的橱窗内容完全隔离，不会串用。
- AC5：删除对话时，该对话关联的橱窗卡片级联删除。

#### P0-04 图表/表格/文字结论可加入橱窗

**描述**：将 AI 消息中的内容块化（识别 echarts 代码块、plotly 代码块、Markdown 表格、关键结论段落、公式计算结果等），每个可操作块提供"加入橱窗"入口。加入后显示"已加入"状态，可取消留存。防重复加入。

**验收标准**：
- AC1：AI 消息渲染时，自动识别并标记以下内容块类型：echarts 图表、plotly 图表、Markdown 表格、公式块（KaTeX display）、可标记的文本结论段（用户可框选或点击段落加入）。
- AC2：每个内容块右上角悬浮显示操作按钮组，至少包含"加入橱窗"按钮。
- AC3：点击"加入橱窗"后，该块以卡片形式出现在右侧橱窗顶部（或末尾），按钮状态变为"已加入 ✓"。
- AC4：同一内容块不可重复加入橱窗（基于 message_id + block_index 去重），重复点击提示"已加入"。
- AC5：点击"已加入"状态可取消留存，对应橱窗卡片同步删除。
- AC6：加入橱窗时自动捕获数据来源上下文（当前 system_context 中的样品标签、字段信息），写入卡片 `data_source` 字段。

#### P0-05 橱窗内容长期保存

**描述**：橱窗内容持久化到数据库，页面刷新、关闭浏览器、退出重登、切换对话、一段时间后重开均不丢失，且卡片排序保持。

**验收标准**：
- AC1：橱窗卡片通过后端 API 持久化到 `ai_showcase_item` 表，含 `sort_order` 字段记录排序。
- AC2：页面刷新后重新打开同一对话，橱窗卡片内容、标题、排序与刷新前完全一致。
- AC3：退出登录后重新登录，橱窗内容不丢失。
- AC4：关闭浏览器后隔天重新打开，橱窗内容仍在。

#### P0-06 橱窗内容排序、删除、重命名、展开

**描述**：橱窗卡片支持拖拽排序、删除、修改标题、展开查看完整内容（图表全尺寸 / 表格完整 / 文本全文）。

**验收标准**：
- AC1：卡片支持拖拽调整顺序，松手后 `sort_order` 即时持久化，刷新后顺序保持。

- AC3：卡片标题默认自动生成（如"图表 · 样品A vs 样品B"），支持双击/点击编辑按钮重命名，回车确认。
- AC4：卡片默认显示缩略预览（图表小图 / 表格前 3 行 / 结论前 2 行），点击"展开"后弹出全屏 Modal 或就地展开显示完整内容。

**描述**：点击橱窗卡片上的"定位原文"操作后，中部聊天区自动滚动到该内容块的来源消息位置，并短暂高亮该块。

### 5.2 各区域交互要点

#### 左栏 — 历史对话 + 搜索（260px，保持宽度不变）
- 顶部新增搜索输入框（带 `SearchOutlined` 图标、`allowClear`），与现有"对话列表/归档"标题并列或紧随其下。

#### 中栏 — 当前对话区（flex:1，适当收窄以让出右栏空间）
- 整体布局、消息渲染、流式输出、输入区、思考模式开关、数据加载按钮、中断按钮全部保留。
- **核心变化**：AI 消息内容块化渲染。`CodeBlockRenderer` 扩展支持 `echarts`、`plotly` 两种语言分支；Markdown 表格、标题段落等也包装为可操作块。每个块右上角悬浮显示操作按钮组（加入橱窗 / 导出图片 / 查看数据）。
- 每个内容块有稳定的 DOM 标识（`data-block-id="msgId-blockIndex"`），供橱窗定位使用。

#### 右栏 — 分析橱窗（~360px，可收起为 ~48px 窄边条）
- **标题栏**："分析橱窗" + 卡片数量角标 + 收起按钮。
- **筛选栏**（P1）：Segmented 控件，按类型筛选。

  - 中部：缩略预览（图表缩略图 / 表格前几行 / 结论摘要）。
  - 底部：数据来源摘要 + 创建时间。
  - 操作区：展开（全屏 Modal）、定位原文、删除。
- **底部操作栏**："生成摘要"/"导出成果"按钮。
- **收起态**：窄边条显示图标 + 数字角标，点击展开。
- **空状态**：引导文案"在对话中点击「加入橱窗」将重要内容留存到这里"。

### 5.3 关键操作流程

#### 流程 A：加载数据 → 生成图表 → 加入橱窗
1. 点击"载入实验数据"→ Modal 选样品 → 确认载入（现有流程不变）。
2. 输入分析问题 → AI 返回含 ` ```echarts ` 或 ` ```plotly ` 图表的回答。
3. 图表块右上角悬浮"加入橱窗"按钮 → 点击。
4. 右侧橱窗顶部新增卡片（带进入动画），按钮变"已加入 ✓"。
5. 卡片自动写入数据来源（样品标签、任务名称）。

#### 流程 B：切换对话 → 橱窗同步恢复
1. 左栏点击另一段历史对话。
2. 中栏加载该对话消息列表。
3. 右栏同步请求该对话的橱窗卡片列表，按 `sort_order` 渲染。
4. 若该对话无橱窗内容，显示空状态。

#### 流程 C：从橱窗定位原文
1. 在橱窗卡片点击"定位原文"。
2. 中栏滚动至 `source_message_id` 对应位置。
3. 该消息中的目标块（`source_block_index`）高亮 2-3 秒。

#### 流程 D：生成分析摘要
1. 橱窗底部点击"生成摘要"。
2. 后端按橱窗卡片排序拼装 Markdown（标题 → 各卡片结论 → 图表引用 → 数据来源）。
3. 弹出预览 Modal，支持复制 / 下载 `.md`。

## 6. 待确认问题

| # | 问题 | 影响 | 倾向方案 |
|---|------|------|----------|
| 1 | 消息内容块化的"块"如何稳定标识？现有 `ai_message.content` 是纯文本，无块结构。 | 影响"加入橱窗"去重与"定位原文"精度。 | 方案A：前端解析 Markdown 时按块出现顺序生成 `block_index`，橱窗存 `message_id + block_index`；方案B：后端在保存消息时预处理块结构写入新表。**倾向方案A**（前端轻量、不改消息表），但需确认 AI 回答中块顺序稳定。 |
| 2 | 历史对话搜索是全量 ILIKE 还是 PostgreSQL 全文索引（tsvector）？ | 影响性能与实现复杂度。数据量不大时 ILIKE 足够。 | **倾向 ILIKE**（`title ILIKE '%q%'` + 子查询消息表），首期数据量可控；若后续对话量增长再升级全文索引。需确认当前数据量级。 |
| 3 | 用户框选文字加入橱窗（P1-02）的交互方式？ | 影响前端实现复杂度。 | 倾向：选中文本后浮动小菜单"加入橱窗"，作为独立"文本"类型卡片。 |
| 4 | Plotly 引入方式：`plotly.js-dist-min`（手动）还是 `react-plotly.js`（封装组件）？ | 影响包体积与维护。 | **倾向 `react-plotly.js` + `plotly.js-dist-min`**，按需引入减少体积。需确认 pnpm 构建配置兼容。 |
| 5 | 橱窗卡片中的图表缩略预览：实时渲染小图 vs 生成 PNG 缩略图存库？ | 影响性能与存储。 | 倾向：实时渲染小尺寸图表（复用 ChartBlock，高度 120px），避免存储图片。需确认大量卡片时性能可接受。 |
| 6 | 成果导出（P0-13）首期交付哪种：Markdown 摘要 / 图片打包 / 简单文档？ | 影响交付范围。 | **倾向 Markdown 摘要**（实现最轻、可下载 `.md`），图片打包与文档排版留 P2。 |
| 7 | 拖拽排序组件选型：`@dnd-kit/sortable` vs `react-dnd`？项目是否已有依赖？ | 影响前端实现。 | 需确认现有 `package.json` 是否已引入拖拽库，优先复用已有依赖。 |
| 8 | 橱窗卡片是否需要在收起状态下也能快速预览（如悬浮展开）？ | 影响 UX 细节。 | 倾向：收起态仅显示数量，不预览，保持简洁。 |
| 9 | 源实验数据后续更新后，橱窗卡片是否需要提示"源数据已更新"？ | 影响数据一致性策略。 | 需求说明书要求"源数据后续更新不影响已保存结果"（快照语义），**倾向不做更新提示**，纯快照。需确认。 |
