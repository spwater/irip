# IRIP 增量 PRD — 实验项目管理

## 1. 项目信息

- **Language:** 中文
- **Programming Language:** Python 3.12+（后端 FastAPI / SQLAlchemy / PostgreSQL 16）、TypeScript + React 18（前端 Vite 5 / Ant Design 5 / TanStack Router+Query）
- **Project Name:** irip-platform
- **原始需求：** 将实验项目从 FlowDefinition 的 `project_name` 文本字段提级为独立实体，实现「实验项目 → 实验任务」两级管理。前端布局改为项目列表卡片→项目内任务列表。
- **范围：** 增量需求，新增 `experiment_project` 实体与对应的前端项目列表/详情页面，FlowDefinition 增加 `project_id` 外键关联，存量数据自动迁移。
- **上游文档：** `docs/prd-department.md`（机构/实验室管理）、`docs/prd-v0.md`、`docs/arch-v0.md`

### 1.1 已拍板决策

| # | 决策项 | 说明 |
|---|--------|------|
| 1 | 前端布局 | 页面主体改为项目列表卡片，点进项目看任务。当前 FlowDetail.tsx 的任务列表变为项目详情的子视图。 |
| 2 | 存量迁移 | 系统升级时自动按 `project_name` 去重创建 `experiment_project` 记录并回填 `project_id`。`project_name` 为空的任务不创建项目记录，保持 `project_id = NULL`。 |
| 3 | 项目状态 | `active` / `archived` 两态。归档后项目内任务只读不可新建。 |

### 1.2 概念关系

```
实验项目 (experiment_project)  ──1:N──  实验任务 (flow_definition)
  ├── code (部门内唯一编码)
  ├── display_name (项目名称)
  ├── status (active / archived)
  ├── owner_user_id (项目负责人)
  └── 部门归属 + 可见性 (A 类多租户模式)
```

## 2. 产品目标

1. **建立实验项目的独立实体管理**：将项目从文本字段提升为可管理的实体，支持创建、编辑、归档等完整生命周期操作，使实验任务可按项目维度组织、聚合与检索。
2. **实现项目 → 任务两级导航体验**：前端从扁平任务列表升级为「项目列表卡片 → 项目内任务列表」两级视图，降低任务查找成本，提升多项目并行场景下的工作效率。
3. **保证存量数据平滑迁移**：系统升级时自动按 `project_name` 去重创建项目实体并回填外键，不丢失历史关联信息，不中断现有业务流程。

## 3. 用户故事

1. **As a** 研究员，**I want** 在实验室运营页面看到项目列表卡片（展示项目名称、任务数量、状态），**so that** 我可以快速浏览和定位我关注的项目。

2. **As a** 研究员，**I want** 点击某个项目卡片进入项目详情页，查看该项目下的所有实验任务列表，**so that** 我可以在项目上下文中管理任务，而不是面对所有部门的全部任务。

3. **As a** 研究员，**I want** 在某个项目内直接创建新的实验任务（自动关联到当前项目），**so that** 新任务自动归属正确项目，无需手动填写项目名称。

4. **As a** 项目负责人，**I want** 创建新的实验项目（填写编码、名称、描述、所属部门），**so that** 为新一轮研究工作建立项目容器。

5. **As a** 项目负责人，**I want** 编辑项目的名称和描述，**so that** 项目信息保持准确。

6. **As a** 项目负责人，**I want** 归档已完成的项目，**so that** 归档后项目内的任务变为只读、不可新建任务，减少活跃列表中的干扰，同时保留历史记录可供查阅。

7. **As a** 平台用户，**I want** 在升级后系统自动将我原有的 `project_name` 文本归属到新创建的项目实体，**so that** 我的实验任务与新项目体系无缝衔接，无需手动迁移。

8. **As a** 研究员，**I want** 查看「归档」状态的项目列表并进入查阅历史任务，**so that** 我可以回顾已完成项目的实验数据。

## 6. 待确认问题

1. **`project_id` 是否允许为空？** 当前设计 `flow_definition.project_id` 为 nullable，兼容存量无项目任务和新建任务时用户选择「不归属任何项目」的场景。但用户决策 1 提到「页面主体改为项目列表」，是否意味着所有任务都必须归属某个项目？如果是，新建任务时 `project_id` 应为必填。**建议**：保持 nullable，P1 阶段提供「未归类任务」入口逐步消化存量，后续再决定是否强制必填。需确认。

2. **存量迁移时 `experiment_project.code` 如何生成？** `project_name` 是自由文本（如"水泥组分研究"），而 `code` 要求部门内唯一且建议为 slug 格式（小写字母/数字/下划线）。迁移时是自动 slugify（中文需音译或 hash）、还是使用 `proj_<短UUID>` 格式、还是直接用 `project_name` 原文？**建议**：使用 `proj_<8位UUID前缀>` 格式自动生成，用户后续可在编辑时修改 display_name。需确认。

3. **存量迁移时 `owner_user_id` 取谁？** 同一个 `project_name` 下可能有多个不同 `owner_user_id` 的任务。迁移创建项目时 `owner_user_id` 取哪一个？**建议**：取该 project_name 下最早创建任务的 `owner_user_id`（即项目的"发起人"）。需确认。

4. **归档项目是否可恢复为活跃？** 当前设计 status 为 active/archived 两态，支持双向切换（归档后可恢复）。是否需要恢复操作？还是归档即永久不可逆？**建议**：支持恢复（与现有 Flow 的 archive/restore 模式一致），恢复后可继续新建任务。需确认。

5. **同一部门下 `project_name` 与 `code` 的唯一性范围？** 存量迁移按 `(department_id, project_name)` 去重，意味着不同部门可以有同名的项目。新建项目时 `code` 在部门内唯一。是否需要跨部门也唯一？**建议**：仅部门内唯一（与 Equipment 一致），跨部门允许重名。需确认。

6. **项目删除是否支持？** 当前需求仅提到 active/archived 两态，未提及删除。是否需要支持删除项目（连带删除项目下任务）？**建议**：不支持项目删除，仅归档。如确需删除，要求项目下无活跃任务且需二次确认。需确认。
